# Parameter Analysis for Regime Detection

This directory contains scripts for analyzing FLOSS hyperparameter importance using BART models with FIRM, Permutation, and SHAP methods.

## Files

- **`parameter_analysis.R`**: Main analysis script (standalone, can be run directly)
- **`../../helpers/parameter_analysis_helpers.R`**: Helper functions for BART training and importance analysis

## Usage

### Basic Usage

Run the script with default settings (malignantventricular dataset, f3_weighted metric):

```bash
Rscript scripts/regime_detection/evaluation/parameter_analysis.R
```

### Change Dataset or Metric

Edit the configuration section at the top of `parameter_analysis.R`:

```r
DATASET <- "malignantventricular"  # Change to: afib_regimes, vtachyarrhythmias
METRIC <- "f3_weighted"             # Change to any metric from CSV
```

Available metrics:
- `f1_classic`, `f1_weighted`, `f3_classic`, `f3_weighted`
- `recall_4s`, `recall_10s`, `precision_4s`, `precision_10s`
- `edd_median_s`, `fp_per_min`
- `nab_score_standard`, `nab_score_low_fp`, `nab_score_low_fn`

### Clear Cache

To force recomputation (e.g., after changing CV parameters):

```bash
rm -rf output/parameter_analysis/
```

## Output

The script generates:

1. **Console Output**: Progress messages and summary statistics
2. **Plots** (printed to screen):
   - Parameter interactions (6 pairs)
   - Variable importance comparison (FIRM, Permutation, SHAP)
   - SHAP dependence plots (2×2 grid)

3. **Cached Files** (in `output/parameter_analysis/`):
   - `bart_fitted_{DATASET}_{METRIC}.rds`: Trained BART model
   - `interactions_{DATASET}_{METRIC}.rds`: Interaction analysis results
   - `importances_{DATASET}_{METRIC}.rds`: Importance analysis results (FIRM/Perm/SHAP)

## Configuration Options

Edit these in the script header:

```r
PARALLEL <- TRUE        # Use all available cores (20 cores)
CV_FOLDS <- 5          # Cross-validation folds
CV_REPS <- 1           # CV repetitions
BART_GRID <- 30        # BART tree tuning grid size

NSIM_FIRM <- 100       # FIRM iterations
NSIM_PERM <- 100       # Permutation iterations
NSIM_SHAP <- 400       # SHAP iterations (slowest)
```

## Computation Time

Typical runtime on 20 cores:
- **First run** (no cache): 15-30 minutes
- **Subsequent runs** (with cache): <1 minute

SHAP importance is the slowest step (10-20 minutes).

## Input Data

Expects CSV at:
```
output/regime_detection/{DATASET}/evaluation/models_aggregated.csv
```

With columns:
- `window_size`, `regime_threshold`, `regime_landmark`, `min_gap_samples` (features)
- 14 evaluation metrics (f1, f3, recall, precision, NAB, etc.)

Generated by Python evaluation in `ts-segmentation` project.

## Example Workflow

1. Run default analysis:
   ```bash
   Rscript scripts/regime_detection/evaluation/parameter_analysis.R
   ```

2. Check plots and summary in console

3. Change metric to `nab_score_standard`:
   ```r
   # Edit line 17 in script
   METRIC <- "nab_score_standard"
   ```

4. Re-run (will use cached BART model, only recompute importances):
   ```bash
   Rscript scripts/regime_detection/evaluation/parameter_analysis.R
   ```

5. Analyze different dataset:
   ```r
   # Edit line 16 in script
   DATASET <- "vtachyarrhythmias"
   ```

6. Clear cache and run fresh analysis

## Tips

- **Speed up prototyping**: Reduce `NSIM_SHAP` to 100 (faster but less stable)
- **Check model fit**: Look for RMSE and R² in output. Good fit: R² > 0.7, RMSE < 0.1
- **Metric with many NAs**: Script will abort if >10% NAs. Use different metric.
- **View cached results**: Load RDS files directly in R for further analysis

## Troubleshooting

**Error: CSV file not found**
- Ensure Python evaluation has been run for the dataset
- Check path: `output/regime_detection/{DATASET}/evaluation/models_aggregated.csv`

**Error: Metric not found**
- Check available metrics in CSV header
- Common typo: `f3_classic` vs `f3_weighted`

**Poor model fit (R² < 0.5)**
- Try different metric
- Increase `CV_FOLDS` to 10
- Check if metric has extreme outliers

**Out of memory**
- Reduce `NSIM_SHAP` to 200
- Disable parallel: `PARALLEL <- FALSE` (slower but less memory)
